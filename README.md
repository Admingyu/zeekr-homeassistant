# Zeekr Home Assistant Custom Integration

This repository contains a Home Assistant custom integration ported from `node-red.json`.

## Install locally

Copy `custom_components/zeekr` into the Home Assistant configuration directory at `custom_components/zeekr`, restart Home Assistant, then add **Zeekr** from **Settings → Devices & services → Add integration**. Enter the Zeekr mobile number and SMS code. The integration signs in, discovers supported vehicles, and creates one device per VIN.

The first status update runs during setup. Vehicle status then refreshes every 60 seconds. The Refresh button requests an immediate update.

## Add the sentry video card

Add this module resource under **Settings → Dashboards → Resources**:

| URL | Type |
| --- | --- |
| `/api/zeekr/zeekr-sentinel-card.js` | JavaScript module |

Then add a manual card with this YAML:

```yaml
type: custom:zeekr-sentinel-card
```

The card asks the integration for a short-lived room session, then uses the fixed `@volcengine/rtc@4.69.2` Web SDK to join and render the vehicle's main stream. It reconnects when the room duration or RTC token expires. The browser loads that pinned SDK from unpkg when playback starts, so the dashboard browser must be able to reach `unpkg.com`. The browser receives only the short-lived RTC session token; Zeekr account tokens and request-signing keys stay in the integration backend.

## Entities

Each supported vehicle exposes these entities. The exact entity ID prefix is generated by Home Assistant from the device name; the suffixes below are stable integration unique IDs.

| Node-RED entity | HA platform | Unique ID suffix |
| --- | --- | --- |
| DistanceToEmpty | sensor | `distance_to_empty` |
| ChargingState | binary_sensor | `charging` |
| Battery | sensor | `battery` |
| InteriorTemp | sensor | `interior_temperature` |
| Engine | sensor | `engine_status` |
| TyreStatusDriver | sensor | `tire_pressure_front_left` |
| TyreStatusPassenger | sensor | `tire_pressure_front_right` |
| TyreStatusDriverRear | sensor | `tire_pressure_rear_left` |
| TyreStatusPassengerRear | sensor | `tire_pressure_rear_right` |
| ServiceLD | sensor | `distance_to_service` |
| TravalTotal | sensor | `odometer` |
| mainBattVoltage | sensor | `main_battery_voltage` |
| averPowerConsumption | sensor | `average_power_consumption` |
| CentralLockingStatus | sensor | `central_locking_status` |
| electricParkBrakeStatus | sensor | `electric_park_brake_status` |
| hvBatteryOptimizeFlag | binary_sensor | `hv_battery_optimization` |
| Location | device_tracker | `location` |
| Refresh | button | `refresh` |
| SentryModeSwitch | switch | `sentry_mode` |

Old-model status entities are not included. The old account endpoint is still used during setup to distinguish old-model VINs from the supported vehicle list. Refresh and sentry actions immediately poll only the selected vehicle; the sentry switch confirms its state from that response. The Node-RED `Unlock` button only triggered a refresh; no unlock control is implemented.

## Actions

`zeekr.get_monthly_statistics` returns a service response and accepts `vin`, `year_month` (`YYYY-MM`), and `account_id`. `zeekr.get_app_messages` accepts `vin` and returns a service response. Use Home Assistant's response-capable action UI or an automation/script that supports action response data.

## Migration from Node-RED

The entity mapping table above maps the old entity names to the new stable ID suffixes. Existing entity IDs and automations are not rewritten automatically; update automations to the new entity IDs after the integration creates the devices.

Vehicle membership is loaded at sign-in. If the account's shared-vehicle list changes, reauthenticate the config entry to discover the updated list.

## Implementation notes

The Zeekr API endpoints and mobile-app signing scheme are undocumented and can change. The integration obtains personal session tokens through the config flow and stores them in the Home Assistant config entry; the fixed app signing values remain in the backend integration. A live account and vehicle are required to verify SMS login, current API response fields, remote sentry commands, and playback from the HA dashboard.
